# 核心开发信念

> 这些是不可违反的原则，所有代码变更都必须符合这些信念。

---

## 1. 安全第一

**信念：** 安全不是可选项，是默认行为。

- 所有用户输入都是不可信的，必须验证和清理
- SQL 查询必须参数化，绝不拼接字符串
- 输出到页面的内容使用 Vue 模板绑定，禁用 `v-html`
- 密码必须 bcrypt 加密，JWT 密钥必须足够复杂
- 上传文件必须验证 MIME 类型和大小

**违反此信念的代码必须立即修复。**

---

## 2. 前后端分离

**信念：** 前端和后端只通过 API 通信，职责清晰。

- 前端只负责 UI 渲染和用户交互
- 后端只负责业务逻辑和数据处理
- 前端不直接操作数据库
- 后端不生成 HTML
- API 是契约，变更需兼容

---

## 3. 分层职责

**信念：** 每一层只做自己的事，不越界。

- routes 只做路由映射，不写业务逻辑
- controllers 处理业务，不写 SQL
- db 层封装数据操作，不处理业务
- middleware 做预处理，不改变业务结果

---

## 4. 可测试性

**信念：** 好的代码应该容易测试。

- 函数应该有明确的输入和输出
- 避免隐藏的副作用
- 依赖应该可注入
- 新功能必须有测试覆盖

---

## 5. 一致性优于个性

**信念：** 团队协作中，一致性比个人风格更重要。

- 遵循现有代码风格
- 使用 ESLint + Prettier 强制执行规范
- 命名、文件组织、注释风格保持统一
- 不确定时，参考现有代码

---

## 6. 渐进增强

**信念：** 功能可以逐步添加，但基础必须稳固。

- 先确保核心功能正确，再添加增强功能
- 安全、性能、可访问性是基础
- 动画、特效是增强
- 不为了炫技牺牲稳定性

---

## 7. 错误处理

**信念：** 错误是正常的，关键是如何处理。

- 所有异步操作必须有错误处理
- 用户看到友好的错误信息
- 开发者看到详细的错误堆栈
- 不要吞掉错误

---

## 8. 性能意识

**信念：** 性能是用户体验的基础。

- 图片上传后考虑压缩
- 数据库查询使用索引
- 前端使用懒加载
- 避免不必要的重渲染

---

## 检查清单

在提交代码前，检查：

- [ ] 是否有安全隐患（XSS、SQL 注入、文件上传漏洞）
- [ ] 是否遵循分层架构（route → controller → db）
- [ ] 是否有输入验证
- [ ] 是否有错误处理
- [ ] 是否通过 ESLint 检查
- [ ] 是否符合现有代码风格
