# v1.3.0 Release Notes

> 覆盖范围：v1.2.1 → v1.3.0
>
> 兼容性：数据库无结构变更，可直接升级；后端列表接口新增 `pageSize=0`（不分页）语义，管理端不再分页。

## 新功能：首页文章 3 列 × 6 行

- 首页文章列表每页 18 篇（3 列 × 6 行），桌面端固定三列布局，单屏信息密度提升
- 平板（≤1024px）自动降为 2 列，移动端保持单列，响应式体验不受影响
- 加载骨架屏同步为 18 张，减少加载过程中的布局跳动与滚动错位

## 修复：后台文章管理拖拽排序无法跨页

- 问题根因：原列表每页仅 10 篇，拖拽排序只作用于当前页，第一页文章无法拖到第二页
- 修复方案：文章管理改为一次列出全部文章（不再分页），任意两篇文章之间均可直接拖拽排序
- 排序仍仅在无筛选（状态、关键词均为空）时可用，避免把筛选子集的顺序写回全局
- 删除文章后直接刷新完整列表，移除分页相关的翻页回退逻辑

## 后端变更

- `/api/posts/admin` 等列表接口支持 `pageSize=0`：表示不分页、一次返回全部匹配文章
- 校验器与分页工具同步适配：`pageSize=0` 时返回 `totalPages: 1`，其余分页行为完全不变

## 工程与部署

- `.gitignore` 新增忽略 `*.bat` 与 `*.docx`（个人启动脚本与文档不入库）
- 移除 `start.bat` 一键启动脚本
- 新增 v1.2.0 / v1.2.1 Release Notes 归档

## 发行版压缩包（Assets）说明与使用方法

本版本随 Release 附带三个压缩包，解压后顶层目录分别为 `server/`、`dist/`、`data/`：

| 压缩包 | 包含内容 | 用途 |
|--------|----------|------|
| `server.tar.gz` | 后端全部源码（不含 `node_modules`、`.env`、`uploads/` 图片） | 安装 / 更新后端服务 |
| `dist.tar.gz` | 前端生产构建产物（`index.html` + `assets/` + `robots.txt` 等） | 安装 / 更新前端静态站点 |
| `data.tar.gz` | 数据目录（`blog.db` 数据库） | 数据迁移、恢复或新站初始化 |

### 全新部署（新服务器）

1. **解压后端**：将 `server.tar.gz` 上传到站点根目录并解压，得到 `server/` 目录
2. **安装依赖**：`cd server && npm install`
3. **配置环境**：复制 `.env.example` 为 `.env`，务必设置 `JWT_SECRET`（`openssl rand -hex 32`）、Nginx 反代时设置 `TRUST_PROXY=1`
4. **导入数据（可选）**：将 `data.tar.gz` 解压到项目根目录，得到 `data/blog.db`（如已有数据可跳过）
5. **启动后端**：宝塔「Node 项目管理」添加项目，启动文件 `server/app.js`，端口 3000
6. **部署前端**：将 `dist.tar.gz` 解压到站点目录，得到 `dist/`，站点根目录指向 `dist/`，并按 README 配置 `/api`、`/uploads`、`/sitemap.xml` 的 Nginx 反代
7. **访问验证**：HTTPS 访问站点，登录后台确认文章、图片、排序均正常

### 覆盖升级（已有站点更新 v1.3.0）

> 覆盖前务必备份数据库：`cp -r data data.bak`

1. **后端**：解压 `server.tar.gz` 覆盖 `server/`（包内不含 `.env`、`uploads/` 图片，不会覆盖服务器上的配置与上传图片）→ 宝塔重启 Node 服务
2. **前端**：解压 `dist.tar.gz` 覆盖站点 `dist/` → 浏览器强制刷新（Ctrl+F5）一次
3. **数据**：仅当需要恢复/迁移数据时才解压 `data.tar.gz` 覆盖 `data/blog.db`，覆盖后重启后端

### 注意事项

- `data.tar.gz` 内含完整数据库（文章全文、用户密码哈希、浏览记录），**若本 Release 为公开可见，请谨慎上传**；建议改为私有 Release，或仅提供不含真实数据的示例包
- 上传图片目录 `server/uploads/` 不在任何包内，迁移服务器时需单独备份该目录
- 后端版本与数据库完全兼容（无结构变更），无需执行迁移脚本
- 升级后端后必须重启，否则管理页会因旧校验器拒绝 `pageSize=0` 而提示「加载文章失败」
