# v1.3.2 Release Notes

> 覆盖范围：v1.3.1 → v1.3.2（对应提交 `6cd2a84`）
>
> 兼容性：数据库无结构变更、无新增依赖。覆盖 `server/` 与 `dist/` 后重启 Node 即可，无需 `npm install`、无需数据迁移，服务器上的 `.env`、`data/`、`uploads/` 均不受影响。

本版本为第二轮全量代码审查的修复批次，共 13 项：1 项高危、6 项中危、6 项体验与健壮性改进，并新增 4 个回归测试。

## 高危修复：后台编辑器跨文章「串页」

- 问题根因：后台 `Layout` 的 `<router-view>` 未绑定 `:key`，「写文章」与「编辑文章」共用同一个 Editor 组件，Vue 原地复用实例——`onMounted` 不重跑、表单不重置
- 后果：在 `/admin/posts/1/edit` 点击侧边栏「写文章」时表单仍保留文章 1 的内容，点「发布」即用旧文章数据创建重复文章；反向路径则可能用空表单覆盖已有文章
- 修复方案：`<component :is="Component" :key="route.path" />`（与前台 `DefaultLayout` 既有模式对齐），跨路由强制重建实例并按新 id 重新拉取文章
- 附带回归测试：create → edit 导航时断言按新 id 重新请求（移除 `:key` 该测试必失败）

## 安全加固

- **登录限流增加账号维度**：同一用户名 15 分钟内失败 5 次后锁定该账号（只计失败、不计成功）。此前仅有 IP 维度限流，反代「追加式」X-Forwarded-For 配置下可被伪造 IP 绕过无限爆破；账号维度不依赖任何代理配置，是兜底的防爆破层
- **`.env.example` 注明 XFF 正确配置**：`TRUST_PROXY=1` 必须配合 Nginx 覆盖式 `proxy_set_header X-Forwarded-For $remote_addr;`；更稳妥的写法是 `TRUST_PROXY=127.0.0.1`（仅信任本机代理）
- **头像路径校验收紧**：`PUT /api/auth/profile` 的 `avatar` 从「任意 `/` 开头的相对路径」收紧为仅接受 `/uploads/` 前缀（原规则会放行 `//evil.com` 这类协议相对 URL），并增加 500 字符长度上限
- `express-rate-limit` 的 `max` 参数更名为 `limit`（v7+ 新名，消除弃用警告）

## 后端修复

- **草稿省略 `content` 字段不再 500**：创建/更新草稿时请求体不含 `content` 的，入库兜底为空串（此前触发 `NOT NULL` 约束返回 500）
- **SQLite 约束错误映射补全**：`SQLITE_CONSTRAINT_NOTNULL` 映射为 400「必填字段缺失」（此前落入 500）；错误处理中间件增加 `headersSent` 防护，响应中途出错时不再二次抛异常
- **users 表时间格式统一**：修改密码、更新个人信息的 `updated_at` 从 `CURRENT_TIMESTAMP`（无时区旧格式）统一为 UTC ISO（`strftime('%Y-%m-%dT%H:%M:%fZ','now')`），与 posts 表 v1.3.1 的时间统一口径一致
- **`updateProfile` 语义修正**：字段「未提供」（undefined）保留原值、「空串」表示清空，与分类的半更新语义对齐（此前空串被吞、无法清空昵称/头像）
- **优雅关闭**：收到 SIGTERM/SIGINT 后先停止接收新连接、断开 keep-alive、等待在途请求处理完毕再关闭数据库退出（10 秒超时兜底），PM2/宝塔/容器重启不再硬断请求

## 前端修复与体验

- **搜索页翻页前进/后退同步**：浏览器返回上一页时结果与 URL 页码不再脱节（watch 补监听 `page` 参数，与首页行为对齐）
- **已发布文章转草稿需确认**：点「保存草稿」会弹窗告知「文章将立即下线且原发布时间会被清除」，确认后才执行（此前静默下线且发布时间不可恢复）
- **会话过期可留在编辑页**：登录过期弹窗中点「取消」后不再被强制跳回列表，用户可留在页面复制未保存内容；其他加载失败增加明确提示
- **置顶后刷新列表**：置顶/取消置顶后列表顺序与服务端一致，消除其后拖拽排序时「置顶分组校验」的误报
- **首页加载失败明确提示**：后端异常时弹出错误提示，不再误显示为「暂无文章」
- **后台移动端滚动锁清理**：侧边栏菜单展开时被登出跳转的边缘场景下，`overflow: hidden` 不再残留导致登录页无法滚动

## 测试

- 新增 4 个回归测试：admin Layout 跨路由重建 Editor、转草稿确认（取消 / 确认两条路径）、草稿请求体省略 `content` 入库
- 修正 `editor.test.js` 中 `useToast` mock 的形状错误（与真实返回结构一致，避免后续用例误炸）
- 全量测试：后端 30 个、前端 23 个全部通过；lint 0 error

## 覆盖升级（v1.3.1 → v1.3.2）

> 覆盖前建议备份数据库：`cp -r data data.bak`

1. **后端**：解压 `server.tar.gz` 覆盖 `server/`（包内不含 `.env`、`node_modules`、`uploads/` 图片，不会影响服务器上的配置与上传文件）→ 重启 Node 服务（PM2：`pm2 restart blog-server`）
2. **前端**：解压 `dist.tar.gz` 覆盖站点 `dist/` → 浏览器强制刷新（Ctrl+F5）一次
3. **无需** `npm install`（依赖无变化）、**无需**数据迁移（schema 无变化）、本版本不附带 `data.tar.gz`

### 行为变更提醒

- 同一账号 15 分钟内登录失败 5 次将被锁定 15 分钟（管理员自己密码连续输错同样会触发，等待或重启 Node 进程即可重置）
- `PUT /api/auth/profile` 传空串现在表示「清空该字段」而非「保留原值」；`avatar` 仅接受 `/uploads/` 前缀路径（前端目前无头像功能，无实际影响）
