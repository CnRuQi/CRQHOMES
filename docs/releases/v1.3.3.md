# v1.3.3 Release Notes

> 覆盖范围：v1.3.2 → v1.3.3（对应提交 `b0b68b6`）
>
> 兼容性：数据库无结构变更、无新增依赖。覆盖 `server/` 与 `dist/` 后重启 Node 即可，无需 `npm install`、无需数据迁移，服务器上的 `.env`、`data/`、`uploads/` 均不受影响。

本版本为前两轮代码审查遗留项（编号 #9 - #22）的分诊批次，共处理 8 项：6 项修复、1 项部分修复、1 项经评估不修，并顺带补齐一批无障碍属性。

## 功能修复：跟随系统主题此前完全不生效

- 问题根因：`initTheme()` 的「有存档」与「无存档」两个分支都调用 `setTheme()`，而 `setTheme()` 无条件写 localStorage。首次加载后 `theme` 键必然存在，导致 `watchSystemTheme()` 里「没有存档才跟随系统」的判断恒为假——系统深浅色变化的运行时监听器全程是死代码
- 后果：从未手动切换过主题的用户，系统主题变化后页面不再跟随，「跟随系统主题」只在首次加载时生效一次
- 修复方案：拆出 `applyTheme()` 只改 DOM 不落盘；`setTheme()`（用户主动切换）才写 localStorage；`initTheme()` 无存档时按系统偏好渲染但刻意不落盘
- 兼容性处理：历史用户已有的 `theme` 值无法区分是手动选择还是首次加载自动写入，一律视为显式选择，升级后外观不变（见文末「行为变更提醒」）

## 后端修复

- **`create-admin` 用户名长度校验**：新增 3-30 长度校验，与登录验证器 `authRules.login` 对齐。此前可创建 1-2 字符用户名的账号，而登录端要求 3-30，这类账号将永远无法登录且不会给出明确原因
- **`create-admin` 密码不再明文回显**：通过临时接管 readline 的输出通道实现隐蔽输入，提示符改由 stdout 直接输出

## 前端修复

- **路由守卫区分「未登录」与「连不上服务器」**：`fetchUser()` 失败此前一律跳登录页，后端重启或网关 5xx 时刷新后台会被甩到登录页，看起来像被登出。现按 `error.response.status === 401` 分流——确认未登录才按「请重新登录」处理；网络错误或 5xx 时登录页显示「无法连接服务器，请稍后重试」，用户一开始提交登录即清除该提示
- **Toast 相同文案连续触发不再被吞**：`useToast` 每次调用都会新建状态对象，但 Toast 监听的是 `visible` 与 `message` 两个标量。相同文案重复触发时两者都不变，watch 不触发、计时不重置，第二条 toast 会跟着第一条的剩余时间一起消失（例如连续两次保存失败）。新增模块级递增 `seq` 并纳入监听依赖
- **`useCountUp` 返回值去掉多余包装**：由 `return { value }` 改为直接 `return value`（ref 本体）。此前模板中的 `{{ totalPosts.value }}` 只是靠 setup 返回对象内 ref 的隐式解包碰巧能跑，一旦解构或重构就会显示异常
- **Icon 缺失图标不再发起无效请求**：图标名不存在时 `iconSrc` 为空串，`<img src="">` 会向当前页 URL 发一次请求。改为不渲染该元素

## 无障碍

- Toast 增加 `role="status"` 与 `aria-live="polite"`，读屏软件可播报提示内容
- 补齐纯图标 / 纯占位控件的可访问名称：Navbar 主题切换与搜索链接、搜索页清除按钮、后台文章列表的状态筛选与搜索框、编辑器标题输入框、分类模态关闭按钮
- 分类模态支持 Esc 关闭（此前键盘用户无法退出）

> 未纳入本轮：模态框的完整 `dialog` 语义与焦点陷阱（`role="dialog"`、`aria-modal`、Tab 循环、关闭后焦点归还）。后台为单人使用场景，投入产出比偏低，有需要时再补。

## 评估后不修

- **页面标题双头管理**：`router/index.js` 中的 `document.title` 与 `Post.vue` 的 `useHead` 并存，进入文章页时标题会闪变两次。仅影响观感、不影响功能；修复需全站接管 title 逻辑，回归面覆盖所有页面，暂不处理。若日后要修，正确路径是删掉路由守卫里的 `document.title`、全站交给 `useSeo`，路由 meta 仅保留 `defaultTitle` 兜底

## 测试

- 全量测试：后端 30 个、前端 23 个全部通过；`npm run lint` 0 error 0 warning
- 注：本机后端测试需用 Node 24 运行——`better-sqlite3` 由 Node 24 编译，与默认 Node 22 的 ABI 不匹配。属本地环境问题，非代码缺陷；CI 使用 `npm ci` 重新编译原生模块，不受影响
- 手动验证：`create-admin` 输入 2 字符用户名被拦截且提示 3-30、密码在终端无任何回显；Toast 连续触发相同文案时计时正常重置

## 覆盖升级（v1.3.2 → v1.3.3）

> 覆盖前建议备份数据库：`cp -r data data.bak`

1. **后端**：解压 `server.tar.gz` 覆盖 `server/`（包内不含 `.env`、`node_modules`、`uploads/` 图片，不会影响服务器上的配置与上传文件）→ 重启 Node 服务（PM2：`pm2 restart blog-server`）
2. **前端**：解压 `dist.tar.gz` 覆盖站点 `dist/` → 浏览器强制刷新（Ctrl+F5）一次
3. **无需** `npm install`（依赖无变化）、**无需**数据迁移（schema 无变化）、本版本不附带 `data.tar.gz`

### 行为变更提醒

- **跟随系统主题需清一次 localStorage**：升级前已存在的 `theme` 键会被视为用户显式选择，系统主题变化时将不再跟随。想恢复自动跟随，在浏览器控制台执行 `localStorage.removeItem('theme')` 后刷新页面
- **`create-admin` 用户名长度限制生效**：脚本现在拒绝 3 字符以下或 30 字符以上的用户名（与登录端一致）。若此前已创建过此类账号，该账号无法登录，需直接改 `users` 表或用脚本重建
