# v1.4.1 Release Notes

> 覆盖范围：v1.4.0 → v1.4.1
>
> 兼容性：**无数据库结构变更、无新增依赖**，覆盖 `server/` 后重启即可；服务器上的 `.env`、`data/`、`uploads/` 均不受影响。前端本次无源码改动，`dist.tar.gz` 仅按发版流程重新构建（产物内容与 v1.4.0 等价）。

本版本为第三轮代码审查（2026-09-07）的修复批次：前两轮（29 项）修复经逐项回归验证全部在位、零回归，本轮新发现 3 项，修复 2 项、评估保留 1 项。

## 后端修复

- **更新文章不再静默取消置顶**：`PUT /api/posts/:id` 省略 `is_top` 是验证器允许的合法请求，旧代码却把它归零——一篇置顶文章会被静默取消置顶（v1.4.0 修复的「省略 status 静默发布草稿」是同一类缺陷）。现改为保留原置顶状态，与 status、published_at 的「半更新语义」完全对齐。前端编辑器始终显式提交 `is_top`，线上行为不变；受影响的是脚本化调用等 API 直接消费方
- **改密接口补上密码长度上限**：`PUT /api/auth/password` 的新密码增加 72 字节（UTF-8）上限校验。bcrypt 只处理前 72 字节，此前通过 API 设置超长密码会被静默截断——用户以为在用长密码，实际生效的只有前 72 字节。CLI 的 `create-admin` 在 v1.4.0 已有同口径校验，本次补齐 API 侧，两端行为一致（中文密码每字符 3 字节，按字节而非字符校验）

## 评估后保留

- **`updateProfile` 空串清空昵称/头像**：第三轮审查曾建议禁止空串，经查证这是 v1.3.2 有意实现的「空串 = 清空」契约（未提供 = 保留原值），且前端有 `nickname || username` 兜底显示——维持现状不改

## 测试

- 后端 35 → **40** 项（新增：省略 `is_top` 保留置顶状态 1 项；新密码 72 字节边界 4 项，含 25 个中文（75 字节、25 字符）被拒的字节级校验用例）
- lint 0 error 0 warning，`format:check` 通过

## 覆盖升级

```bash
tar -xzf server.tar.gz         # 覆盖 server/
pm2 restart blog-server        # 重启
tar -xzf dist.tar.gz           # 覆盖 dist/，浏览器 Ctrl+F5
```

- 无 schema 变更，无需备份数据库（常规预防性备份仍建议）
- 无依赖变化，无需 `npm install`
- 无行为变更提醒：标准前端流程（编辑器总是显式提交 `is_top`、密码输入框场景）不受影响
