# v2.0.0 Release Notes

> 发布日期：2026-09-13
>
> 覆盖范围：v1.4.1 → v2.0.0
>
> 本版本完成 2026-09-12 至 2026-09-13 的全面安全、数据完整性、前端可访问性和发布工程审计。GitHub Release 建议附带 `server.tar.gz` 和 `dist.tar.gz` 两个部署包。

## 版本摘要

v2.0.0 是一次集中审计修复版本，覆盖后端配置与输入边界、SQLite 迁移、公开读取接口、Markdown 安全渲染、后台编辑器、主题对比度、键盘操作、CI 阻断性和部署文档。

本版本没有新增生产运行时依赖。前端依赖树移除了已不再由源码直接使用的 `highlight.js` 和 `marked-highlight` 条目；生产服务器直接使用构建后的 `dist/` 时不需要安装前端依赖。

## 安全与运行时配置

- 生产环境启动改为 fail-closed：必须设置非占位 `JWT_SECRET`，长度至少 32 个字符，并设置有效的 `SITE_URL`。
- `TRUST_PROXY` 支持明确的代理 IP 列表；本机 Nginx 反代推荐使用 `TRUST_PROXY=127.0.0.1`。
- 生产认证 Cookie 带 `Secure` 标志，站点必须通过 HTTPS 提供。
- sitemap 使用配置的 `SITE_URL`，不再信任请求 Host 作为生产环境回退值。
- 上传响应统一返回 `/uploads/` 路径，即使上传目录配置为绝对路径也不会泄露服务器文件系统路径。
- 文章、分类、个人资料、标签和发布时间输入增加类型及长度边界；文章更新区分“未提供”和“主动清空”。
- 省略文章的 `status`、`is_top`、摘要、封面、标签等可选字段时保留原值；显式空值仍按接口契约执行清空。

## 数据库与 API

- 旧数据库的文章 slug 迁移改为事务执行，碰撞值按稳定的文章 ID 顺序添加后缀，并建立唯一索引。
- 迁移失败不再被静默吞掉，启动日志和测试会保留失败信息。
- 公开文章列表限制 `pageSize` 为 1-50；后台列表保留独立的无分页规则。
- 搜索接口增加每个可信客户端 IP 每 15 分钟 300 次的限流，并限制查询输入规模。
- 归档接口改为分页返回 `page`、`pageSize`、`total` 和 `totalPages`，前端可连续查看全部文章，不再静默截断。
- Markdown 原始 HTML 不执行；内容通过 Vue VNode 渲染，链接协议受限，图片和 HTML 输出经过安全处理，项目继续禁止 `v-html`。

## 前端体验与可访问性

- 修复前台重复 `main`、后台登录表单语义、图标按钮命名、表单标签关联和后台标题层级。
- 后台编辑器在窄屏下不再产生文档级横向溢出，排序操作提供键盘替代方式。
- 修正 Light/Dark 主题的卡片、状态标签、正文和页脚颜色 token。
- 文章真实 Markdown 内容、HTTPS 链接、代码块、懒加载图片和图片加载失败状态均完成回归。
- 编辑器按后台路由懒加载，公开首页不请求编辑器和高亮相关的大型 chunk。

## CI、依赖与文档

- `.github/workflows/code-cleanup.yml` 的 lint、格式检查、测试和构建改为阻断式执行，不再用 `|| true` 隐藏失败。
- 完成 root、server、client 的 clean `npm ci`、依赖树检查和离线审计记录。
- 架构文档改为描述当前真实边界：routes 不直接访问数据库，controllers 通过 `server/db/index.js` 执行参数化 SQL；独立 data-access 层仍是后续整理目标。

## 部署与迁移

升级前请先备份服务器上的 `.env`、`data/blog.db` 和 `server/uploads/`。解压部署包时保留这些服务器数据，不要用 `.env.example` 覆盖 `.env`。

```bash
# 在项目根目录执行
tar -xzf server.tar.gz       # 覆盖 server/

# 后端依赖无变化；只有在服务器依赖需要重装时执行
cd server
npm ci --omit=dev

# 重启 Node/PM2/宝塔 Node 项目，启动时自动执行数据库迁移
cd ..
tar -xzf dist.tar.gz         # 覆盖 dist/
```

生产环境至少需要确认：

```env
NODE_ENV=production
JWT_SECRET=<随机且不少于32个字符的密钥>
SITE_URL=https://your-domain.com
CORS_ORIGIN=https://your-domain.com
TRUST_PROXY=127.0.0.1
```

若使用 Nginx 本机反代，请覆盖而不是追加 `X-Forwarded-For`：

```nginx
proxy_set_header X-Forwarded-For $remote_addr;
proxy_set_header X-Forwarded-Proto $scheme;
```
